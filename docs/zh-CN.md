# math-mode-switcher 中文说明

## 这是什么

`math-mode-switcher` 是一个面向 TraeWork 对话场景的轻量 Skill，用来统一数学公式的输出方式。它的核心作用，不是“生成新公式”，而是**让公式以正确的展示模式输出**。

它解决的是人与 AI 在公式沟通中的格式分歧问题：

- 想看效果时，AI 不应只给源码
- 想复制源码时，AI 不应只给渲染
- 想同时看效果和复制代码时，AI 应该稳定输出双模式结果

## 为什么有价值

在需要频繁讨论数学表达的场景里，格式歧义会显著增加沟通成本，尤其包括：

- 论文写作
- 专利撰写
- 技术报告整理
- PDF / LaTeX 文档生成
- 公式审阅、校对与改写

一个稳定的“显示模式切换协议”看起来很小，但它能明显减少重复解释，如“我要的是渲染效果”“我要的是可复制代码”“不要给我 `latex` 代码块”等。

## 支持的模式

### 渲染模式

用于直接查看最终排版效果。

规则：
- 行内公式使用 `$...$`
- 块级公式使用 `$$...$$`
- 多行推导优先使用 `aligned`
- 避免把待渲染公式放进 ` ```latex ` 代码块

适用场景：
- 看别人 LaTeX 的最终效果
- 检查公式视觉布局
- 确认推导展示是否清晰

### 源码模式

用于获取可复制、可复用的公式代码。

细分为：
- `源码模式（Markdown）`
- `源码模式（LaTeX）`

适用场景：
- 粘贴到 Markdown 编辑器
- 粘贴到论文、专利、PDF 工程
- 用于后续自动化排版或模板生成

### 双模式

先输出渲染效果，再输出对应源码。

适用场景：
- 一边确认效果，一边复制代码
- 与他人协作时减少二次确认
- 需要同时保留“可读性”和“可复用性”

## 推荐口令

推荐在对话里直接使用这些固定口令：

- `模式：渲染`
- `模式：源码（md）`
- `模式：源码（latex）`
- `模式：双模式`

如果不想每次写“模式：”，也可以直接说：

- `渲染模式`
- `源码模式`
- `双模式`

## 默认推断逻辑

当用户没有明确说明模式时，Skill 建议按如下逻辑推断：

- 用户说“看看渲染效果”“看看排版” -> 默认 `渲染模式`
- 用户说“复制代码”“用于 PDF”“用于 LaTeX”“用于 Word” -> 默认 `源码模式（LaTeX）`
- 其余模糊情况 -> 默认 `双模式`

## 最佳实践

- 对于需要复制的代码，优先明确说 `Markdown` 还是 `LaTeX`
- 对于块级公式渲染，优先使用 `$$...$$`
- 对于复杂公式，如果渲染不稳定，可先给 `LaTeX` 源码再给简化渲染版
- 对于长期合作对话，可以把“双模式”设为默认协议

## 适合谁用

- 经常和 AI 讨论公式的研究者
- 需要在专利、论文和技术文档中反复搬运公式的人
- 希望减少“格式沟通成本”的高频用户
